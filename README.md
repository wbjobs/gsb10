# 音频指纹重复检测系统

纯前端音频指纹方案：录制或导入音频，提取指纹入库，检测任意音频与曲库中的重复片段并高亮显示。无后端，全部数据存于 IndexedDB。

## 运行

```bash
# 任意静态服务器，例如：
python3 -m http.server 8080
# 打开 http://localhost:8080
```

> 需要通过 http(s) 访问（Worker 与 IndexedDB 在 file:// 下受限）。录音功能需要麦克风权限。

## 使用

1. **导入音频**：批量导入音频文件（mp3/wav/m4a/ogg 等浏览器可解码格式），自动解码、重采样、提取指纹并持久化。
2. **录音入库**：直接从麦克风录音加入曲库。
3. **重复检测**：选择音频文件或录音作为查询，系统在秒级内返回与库中重复的歌曲及**重复片段的时间区间**，点击结果卡片查看双向波形高亮对比。
4. **扫描库内重复**：对曲库做全量两两查重，找出库内重复歌曲/片段。
5. 曲库持久化于 IndexedDB，刷新/重启浏览器后索引自动重建。

## 技术架构

```
index.html
├── js/dsp.js      指纹核心：radix-2 FFT → 功率谱 → 谱峰星座图 → landmark 哈希
├── js/worker.js   Web Worker：指纹计算、倒排索引维护、比对、库内查重
├── js/db.js       IndexedDB 封装（songs 元数据 + fps 指纹两个 store）
└── js/app.js      主线程：解码/重采样、UI、波形高亮渲染
```

### 指纹算法（抗噪设计）

- 统一重采样到 **11025Hz 单声道**，分析频段限制在 **250Hz–5kHz**（低码率编码器通常保留该频段，规避高频被砍导致的失配）。
- 2048 点 FFT（Hann 窗，512 步进），自实现迭代 radix-2 + 预计算旋转因子/位反转表，避免依赖第三方库。
- 每帧提取**相对能量门限**（-30dB）的频域局部极大值谱峰，最多 4 个 —— 对整体增益变化、加性噪声鲁棒。
- 锚点 + 目标区（未来 ~1.5s）谱峰配对生成 26-bit landmark 哈希 `(f1, f2, Δt)`，时频相对关系对码率/响度/轻度噪声不变。
- 同一哈希每首歌最多保留 15 次，抑制持续纯音造成的哈希洪泛。

### 海量比对索引

- 倒排索引：`(hash << 32) | (songId << 20 | frame)` 打包为 **BigUint64 排序数组**，8 字节/条；100 首 30 秒歌曲约 51 万条仅 **~4MB**。
- 查询 = 二分查找 + 命中扫描；增量导入通过**有序数组合并**（O(n)）完成，避免全量重排。
- 比对采用**时间偏移直方图聚类**：同一偏移上大量命中即为重复，偏移值直接给出片段对齐位置。
- 判定三重过滤：最低命中数、命中密度（hits/秒）、最小片段时长（3s），实测交叉误报为 0。

### 内存控制

- 只持久化指纹（每首约几万个 32-bit 整数），不存原始音频；波形显示只保留 1000 点峰值包络。
- PCM 通过 **Transferable 零拷贝**在主线程与 Worker 间传递，用完即释放；逐首串行导入避免峰值内存叠加。
- 实测：100 首曲库索引 ~4MB，整体堆占用远低于 500MB 上限（页面右上角实时显示堆内存）。

## 验收标准对照

| 标准 | 实测（Node 测试，`npm test`） |

## 已知限制

- songId 为 12-bit（哈希打包位宽），曲库上限 4095 首。
- 重复片段最短报告时长 3 秒，更短的相似段不报告。
- 音频解码能力取决于浏览器（decodeAudioData 支持的格式）。
