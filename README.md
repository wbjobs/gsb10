# 本地音频指纹与重复片段检测

纯前端实现，无后端：

- Web Audio / OfflineAudioContext 解码、下混并重采样到 8 kHz 单声道。
- AudioWorklet 录音，导出本地 WAV，可直接入库或作为查询音频。
- Web Worker 执行 FFT、频谱峰提取、指纹生成、倒排索引构建与查询，不阻塞 UI。
- IndexedDB 持久化原始音频、波形、指纹分片和倒排索引分片，刷新后自动恢复。

## 本地运行

必须通过 HTTP 访问，ES Module Worker 和 AudioWorklet 不支持 `file://`：

```bash
npm run serve
# 或
python3 -m http.server 8080
```

打开 `http://localhost:8080`。

## 指纹算法

1. 使用 512 点 FFT，Hann 窗，32 ms 帧移。
2. 只保留约 62.5 Hz–3.4 kHz 语音/音乐主要能量区。
3. 对频谱做局部峰检测，五个频带每帧保留强峰，配合预加重增强高频细节。
4. 将锚点峰与未来 0.25–2.05 秒的目标峰组成 landmark，量化为 20-bit 哈希。
5. 查询时扩展为 3×3 频率容差，降低 MP3/AAC 低码率导致的 ±1 bin 漂移。
6. 用“曲目 + 时间偏移”投票过滤随机碰撞，再按一致偏移聚类，输出双方的重复时间区间。

## 性能与内存

指纹库默认支持 4095 个曲目 ID，全库指纹索引上限 600 万个事件。以 100 首 3 分钟音频的 Node 合成压测为参考：

- 指纹总量约 69 万。
- 倒排索引约 9 MB。
- 查询约 0.1 秒。
- 查询期间 JS 堆约 13 MB；浏览器中加上音频和 IndexedDB 缓冲仍远低于 500 MB。

运行方式是逐首解码和提取，避免同时保留上百首 AudioBuffer；查询时只持有查询 PCM、全局索引和固定大小票仓。

## 测试

```bash
npm test
npm run benchmark
```

- `basic-test` 使用非线性失真、噪声、轻微频率响应变化验证同一音频的重复识别。
- `benchmark` 构建 100 首独立旋律库，并检测加噪版本，输出索引大小、查询耗时和堆内存。

## 注意

浏览器的 IndexedDB 配额由磁盘剩余空间和浏览器策略决定；Chrome/Edge 通常能满足本地百首歌曲库。指纹不是 DRM，极端变速、大幅变调、强降噪或严重削波仍可能降低召回率。
